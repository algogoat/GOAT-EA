---
name: goat-portfolio-build
description: Build, compare, save and export GOAT portfolios from a fixed strategy pool through the installed desktop agent API, including supported exposure evidence.
---

Read the installed `desktop-agent-workflow.md` and, when using exposure data,
`portfolio-exposure-replay.md` beside the controller start guide. Discover
`goat.exe desktop agent.status`, `optimizer.defaults`, libraries, jobs and vault
before choosing methods. Use the packaged transport and authenticated data directory;
never copy bearer credentials into requests, logs or support files.

Freeze the user's exact strategy pool, SET/CSV identities and original sizing.
Reuse an identical existing library; otherwise prepare/finalize an import and
inspect coverage and rejections. SET files alone do not provide performance curves.
Explicit strategy IDs still pass the sift and do not bypass its filters.

Plan from advertised defaults with explicit effective settings and a bounded
objective. Preserve plan hashes and use stable request IDs for identical uncertain
mutations; inspect retained receipts/jobs before retrying. Use fresh IDs for reads.
Monitor actual completed/failed work and distinguish checkpoints from final results.

Compare exact candidates by common-period performance, sampled drawdown,
concentration, sizing and overlap. For an already selected basket, use advertised
fixed-basket analysis instead of starting an unnecessary search.

Direction-crowding penalties are not simulated exposure-filter execution. Only use
filter-on results when the installed capability has the required native sequence
evidence and coverage. Preserve its disclosed approximation/qualification limits.

Save alternatives under distinct names and export through the API. Verify returned
file hashes/member identity. A saved portfolio or ZIP is not a deployed portfolio
and does not authorize replacing live positions or enabling trading.
